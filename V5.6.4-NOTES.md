# V5.6.4 — Scrollable nest arrangement on touch screens

## Cause

`NestScene.sync()` assigned `touch-action: none` to the entire WebGL canvas while arranging. This suppressed vertical page scrolling before raycasting, including empty floor, walls and transparent margins. Pointer-event `preventDefault()` alone cannot distinguish scene objects inside one canvas for native scroll arbitration.

## Fix

- Keep the canvas `pan-y pinch-zoom` in both visit and arrangement modes, including loading.
- Scope non-passive native touch listeners to the canvas. At the first touch, use the existing exact resident-mesh raycast; claim only a real resident hit in arrangement mode.
- Never claim a blank-origin gesture later when it crosses a toy. Empty-space scrolling preserves selection, allowing the user to reach that toy's controls.
- Route claimed native touches through the existing floor projection, furniture constraints and placement callbacks. Separate the compatibility pointer stream to prevent duplicate moves or premature cancellation. Mouse/pen pointer capture and visit-mode taps remain supported.
- Reset on touch cancellation, multiple fingers, hidden/inactive scene, blur and context loss; rollback interrupted drags. Dispose scoped listeners on unmount.
- Add a short hint: 按住玩具拖动 · 空白处上下滑动.
- No changes to accounts, saved collections, room assets, audio, stories or postcard generation.

## Validation

- TypeScript check and production build/verification passed.
- 149 automated tests passed, including 7 new touch routing regressions: blank/edge scrolling, crossing residents, vertical/horizontal dragging, release outside the canvas, visit mode, multi-touch/cancellation, identifiers/reset/cleanup.
- At a 390 × 844 browser viewport, exercised edge scrolling to the tray, selecting a resident, left/right rotation, mouse dragging, and cancelling edits. The room audio remained `playing`. No runtime errors; only the existing Three.Clock deprecation warning.
- Native iPhone/WeChat touch input is not available in this environment. Viewport/mouse checks do not claim physical-device validation; the mobile touch routing is covered by the automated tests and needs a phone smoke check.

Touch cancellation behavior references the [W3C Touch Events definition](https://www.w3.org/TR/touch-events/#the-touchstart-event). No whole-page touch blocker or invisible drag overlay was added.
