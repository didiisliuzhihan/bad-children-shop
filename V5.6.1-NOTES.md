# V5.6.1 · Guest room and fireplace hotfix

- Removed the leftover localhost-only gate from guest room saving. Guest layouts now save in the current browser, with an explicit no-cross-device-sync notice. Storage failure keeps the edits and reports an actionable message.
- Fixed fireplace audio routing: its Pages-hosted MP3 is resolved explicitly, independently from the Storage-hosted BGM. Gesture and mute recovery retain the correct recording URL.
- Added honest room-audio loading, muted/blocked and failure feedback; a failed recording can be retried without synthesizing substitute noises.
- Account cloud-save and guest storage remain separate. No schema, account records, collections or existing room layouts were reset.
- TypeScript/build and 133 tests passed. Browser verification covered guest save, room/arrangement playback, mute/resume and absence of runtime errors. Nonempty guest-layout restoration and storage-failure behavior are exercised against the actual room component in regression tests.

Root-cause evidence: the old derived Storage URL returned HTTP 400; the actual release MP3 returned HTTP 200 and matched the user recording. The old guest branch rejected every production hostname before attempting local storage.
