# V5.6.2 — private story scene photos

- Confirmed the reported solo_popcorn story had NULL media; this was not an image display failure on the phone.
- Missing-photo stories are prioritized when the same eligible scene event next occurs. Completion returns the original story event ID even when deduplication prevents another story row.
- Repeat photos are actual new scene captures and are labeled “这个小故事再次发生时”, with their own capture timestamp; no invented historical image.
- New machine draws exclude stories until their private photo is attached. Existing outstanding draws refresh current media without changing the draw or its outcome.
- Capture retries at 8/9.5/11 seconds within the same active event. Failed captures show feedback and can be repaired on recurrence.
- Completed scene photos have an owner-scoped IndexedDB retry buffer, backed by private cloud storage. Upload retries survive reload, do not upload under a different account, and never overwrite an existing photo.
- Concurrent upload retries return the saved winner. Collected cards update their photo in memory after upload.
- The existing guest layout save and explicit fireplace URL fixes from V5.6.1 are preserved.

Validation: 138 local tests pass; production build passes. The actual QA room generated a no-photo solo_popcorn return story, replayed the event, and attached a 960×960 PNG through the authenticated API. Direct anon/authenticated access to the life RPC remains revoked. Private media stays in the existing private bucket. No real player's collection or story records were manually altered.

Database change: Supabase migration nest_story_photo_completion updates only bc_nest_step; authoritative source is supabase/nest-life-preview.sql. Edge version 6. Existing security advisories are unchanged (backend-only tables intentionally have no public policies; legacy anonymous own-collection policy remains; leaked-password protection is disabled).

Limits: old images that were never captured cannot be recovered. Corresponding residents must be placed and eligible for a repeat scene before an old card can receive an honestly labeled new photo. A real iPhone/WebKit session was not available; do not claim physical-phone certification. The transactional SQL fixture could not run with the read-only SQL tool role; live authenticated API/browser validation is used instead.
