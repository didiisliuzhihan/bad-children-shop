# V5.6.6 — Responsiveness plan A

Release authorized by the owner after local playing. Account Edge version 8 was deployed and live-validated on 2026-09-09 UTC before publishing this frontend. No existing player records were changed for release QA.

## User-requested local playground

The owner chose local preview/playing before deciding whether to publish. The isolated 4178 device-only playground remains available; see `previews/local-play/README.md`. It uses an IndexedDB sample adapter, not production accounts. It is a development fixture, never the public entry. Local response speed is not evidence of cloud speed. Current full test total: 178; device-local labels do not change production's default cloud behavior.

## Changes

- Keep/save/quest use small server-confirmed patches. The UI displays progress immediately, then updates just the confirmed record. Keeping a capsule no longer triggers or awaits a full collection reload. A successful-looking animation is not a substitute for a durable server acknowledgement.
- An older background snapshot cannot overwrite newer confirmed writes. Same-session token refreshes do not discard active saves or repeatedly reload collections. Failed background reads preserve loaded content and expose a small retry notice; initial authentication failures still require recovery/login.
- Read/media and idempotent keep/document-save requests have one bounded retry for transient connection/service failures. Retries reuse the draw ID or document revision. Opposite decisions on resolved draws return a conflict, not false success. A lost document response is acknowledged only for identical canonical content at the exact next revision, never by overwriting a newer edit.
- Collection loads carry private photo metadata without signing each file. Visible/near-visible photos request owner-checked access URLs in batches of at most 24. URLs are deduplicated, expiry-cached and invalidated on account replacement. Video thumbnails request only their still poster. Photo failure is local to the image; it does not block keeping or viewing the rest of the collection.
- Card panes display the existing artwork and selectable text without waiting for canvas/font composition. Hidden card panes do not start their artwork/export work. High-resolution PNGs are prepared after the first image paint, have bounded image-decode/font/encode waits, and are cached by rendered content. Optional font failure uses a system fallback. Art/export failures preserve the readable preview and retry controls.

## Unchanged / not claimed

- No model, lighting, material, shadow or audio-quality reductions. No hosting migration or new database schema/indexes. Account ownership/session verification, private storage, quest eligibility and conflict protection remain in place.
- Private stories stay private and unstamped. Missing historical scene photos are not fabricated; this change improves delivery of photos that actually exist.
- The reported physical-phone arrangement scrolling bug is STILL OPEN. The floor-only touch-interaction redesign is separate. Desktop narrow-viewport testing does not prove touch/WebView behavior.
- This is not a measured guarantee for every phone/network. Real-player/physical-iOS acceptance remains separate from the isolated live API checks below.

## Validation

- TypeScript, production single-file build, build verification and Pages artifact preparation passed (691 modules, 2,245,573 bytes HTML; about 603.78 kB gzip). No external script/style references or inlined binary media were introduced.
- 178 automated tests (174 production regression checks and 4 isolated-playground checks): confirmed toy/story patches, stale-read isolation, token-refresh isolation, bounded retries/deduplication, exact-revision document retries, real Edge-handler branches with mocked services, private-media batching/expiry/owner changes, hidden/lazy image behavior, and existing release regressions.
- Local browser-only component acceptance at 390px width: all five native card previews keep their text/date inside the card; all five produce decoded 1080×1440 PNGs; repeated opens reuse prepared cards. Deliberately missing art preserves copy and exposes both art and high-resolution retries, with no full-page failure overlay.
- The component fixture is `review/performance-a.html`; it imports production components but has no account provider, cloud writes, collection rewards or shop entry. It is not in the published entry bundle.

## Live release validation / order

The backwards-compatible account Edge was deployed first with all five files, including `documentRetry.mjs`. Legacy V5.6.5 requests without `responseMode: patch`/`deferMedia` retain their old responses.

`node scripts/verify-performance-a.mjs --live` passed 23 live checks using one fresh QA account: registration, empty read, two draws, confirmed keep plus identical retry, opposite-decision conflicts, quest patch, nest revision/retry/conflict, private QA-pixel upload/draft, deferred load, deduplicated batch signing, fetched PNG byte equality, owner/batch-size rejection, legacy load, logout and revoked-session rejection. No test draft was shared. Credentials were memory-only; the QA session was signed out.

This run's confirmed keep was 1,924 ms; nest save 1,381 ms; private draft save 762 ms; batched photo signing 969 ms. These are individual endpoint timings, not a before/after benchmark or a promise about all devices. Crucially, acknowledgement did not include a full snapshot or wait for photos.

Security advisor review: account tables intentionally have RLS with no client policies (backend-only); the legacy guest collection read policy and disabled leaked-password screening are pre-existing, unchanged advisories. No permissions were broadened.
